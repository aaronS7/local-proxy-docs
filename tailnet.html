GUIDES / Tailscale links

Your tailnet, clearly linked.

Hostname first. IP second. Existing access stays in your control.

Enable link discovery

./bin/localproxy discover --tailnet
# Or, for an already running instance:
./bin/localproxy reload --tailnet

# Disable and persist that preference:
./bin/localproxy reload --tailnet=false

The flag adds Tailnet hostname followed by Tailnet IP. It reads this machine’s Tailscale status, existing Serve configuration, and listening ports. Hostnames come from Tailscale status; see Tailscale’s MagicDNS documentation for name resolution.

Enable the setting with discover, generate, start, or reload before starting the UI. The current ui --tailnet invocation accepts the flag but does not apply it.

How URLs are chosen

ColumnURL selection
HostnameAn existing Tailscale Serve root proxy for this app, when found; otherwise the machine’s hostname at the original HTTP port.
IPThe Tailscale IPv4 address at the original HTTP port, with IPv6 as fallback.

An existing Serve HTTPS URL keeps its certified hostname. The IP column remains an HTTP URL at the original port, avoiding a hostname certificate mismatch on an IP address. Direct links without a detected matching listener appear as unavailable text. Firewall rules and tailnet access policies still determine whether detected listeners can be reached.

Display does not create access

--tailnet does not change an app’s bind address, create a Serve entry, enable Funnel, or expose the local proxy. An app listening only at 127.0.0.1 remains local to this machine. An app must already have a suitable listener or Serve route for its displayed link to work remotely.

Reach the directory remotely

Serving the directory to your tailnet is a separate setup step. The Go UI must bind to loopback. Use a dedicated Caddy server listening on the machine’s Tailscale IP whose only route proxies to that UI. Keep app routing on its original loopback listeners.

For example, the directory-only server object in an instance-specific Caddy JSON config looks like this. Replace the example IP with your own Tailscale address and choose an available port:

{
  "listen": ["100.101.102.103:18082"],
  "routes": [{
    "handle": [{
      "handler": "reverse_proxy",
      "upstreams": [{"dial": "127.0.0.1:18083"}]
    }]
  }],
  "automatic_https": {"disable": true}
}

This is a server object to merge under apps.http.servers, not a complete configuration or a CLI flag. Use custom instance options to preserve it during browser edits. Full CLI regeneration can replace manual additions. The directory-only route makes arbitrary paths reach the editor instead of app upstreams.

Anyone allowed to reach this editable directory can rename apps. It has same-origin, Host, CSRF, and revision checks, but no separate user account system. Use your tailnet’s access controls to define who can reach it.

Refresh behavior

The static page refreshes its tailnet information when generated. The editable UI caches Tailscale lookups for 15 seconds and refreshes them on requests. A disconnected or unavailable daemon produces an explanatory status; local directory links remain available.

GUIDES / Troubleshooting

Follow the request.

Check DNS, TLS, routing, and the editor one layer at a time.

The domain does not resolve

New configurations use .localhost, which modern browsers resolve automatically. Optional .test names require setup or a manually configured resolver. Check getent hosts app.test or the name under your chosen suffix. It must resolve to loopback for local app routes. Use the quickstart’s curl --resolve command to test routing independently. Check whether browser DNS-over-HTTPS bypasses the local resolver.

HTTPS reports a certificate error

Run localproxy doctor to distinguish DNS, HTTP and system trust failures. Rerun setup with the same registry to install its CA. For a browser with an independent store, import that instance's root.crt. Older engines used wildcard certificates; restart with the current binary for exact-name certificates. Do not disable hostname verification.

A registered app fails

Open its original http://localhost:<port> link. Confirm the app accepts IPv4 loopback connections and its port matches the registry. If it rejects the custom hostname, allow that hostname in the app or set the route’s localhost_host option and reload. App 404s and upstream failures are not replaced with the directory.

An unknown name gets 403

The editable directory restricts Host headers. Use an unregistered single-label name under your configured suffix, such as missing.dev.test, or the machine’s recognized local/Tailscale address. Arbitrary external Host headers are rejected. Static and editable fallback have different Host behavior.

Editing is missing or fails

Use up to start the editor with the proxy. For separately managed processes, check that directory_address is configured, the UI process is listening at that address, and Caddy has reloaded it. The static directory has no editing controls. For an instance-specific admin port, pass --proxy-admin; use --proxy-config to retain its restart snapshot.

Refresh after a revision conflict. If Caddy rejects a browser edit, inspect its logs before retrying. Do not assume the directory confirms active upstream health.

Saved names do not match running routes

CLI commands save the registry before reloading Caddy. A failed reload leaves the new configuration saved, and an unavailable admin endpoint causes automatic reload to be skipped. Check Caddy’s logs and admin address, correct the error, then run localproxy reload. The list command shows merged configuration, not the running proxy’s state.

The map or rename seems ignored

Overrides outrank map entries. Check name_source and project_file in the registry. If both proxy.yaml and proxy.json exist, choose one using -file before the command. Run CLI commands from a directory without an unrelated map, or select the intended file explicitly. The directory can display project-file edits before Caddy has applied them. Run reload after changing the map.

Tailnet links are unavailable

Enable the saved setting with reload --tailnet, rather than ui --tailnet. Check tailscale status and whether the app already has a suitable listener or Serve endpoint. A localhost-only app cannot be reached at the machine’s Tailscale IP just because a link is displayed. Check access rules and firewalls from the other device.

Startup says a port is in use

Inspect ss -ltnp. Give each instance distinct HTTP, HTTPS, admin, and UI ports; keep app ports separate from these. Use ports above 1023 to run without privileged-port permissions. The demo script chooses available ports and avoids your normal registry.

GUIDES / Configuration

Names that stay yours.

Project defaults, persistent overrides, and predictable precedence.

A project map

Put a flat name-to-port map in proxy.yaml:

app: 3000
api: 8080

Or use proxy.json:

{
  "app": 3000,
  "api": 8080
}

Short names gain the configured suffix. Full names under that suffix also work. Ports must be integers and each port must have one name in the map. Use {} for an empty map. Keep one format in a directory; if both exist, select one explicitly on each CLI command that reads the map.

./bin/localproxy -file proxy.yaml generate
./bin/localproxy -file proxy.json generate

Naming precedence

PriorityName sourceHow it changes
1CLI / UI overrideadd, rename, or browser edit
2Project fileEdit the map and run reload
3DiscoveryRandom name when a new HTTP port is found
./bin/localproxy rename app studio
./bin/localproxy reload
# studio.test keeps its name, even if the map still says app.

The project map is never rewritten. remove records a suppressed port, so discovery and the map do not immediately restore it. Use add <name> <port> to restore it. Deleting a map entry removes that file-managed route on reload, while overrides and unrelated discovered routes remain.

There is no reset-override command yet. To return a route to its file default, stop concurrent writers, remove that route’s name_source: "override" field in the registry, and reload.

Which file gets read?

  1. An explicit -file path, when given.
  2. A map in the current working directory.
  3. The remembered absolute project-file path.
  4. A map next to the registry.

A missing remembered file or invalid map causes an error. Files are not watched. The UI reads the map on requests, so it can display an edited default before Caddy has applied it; run reload after changing the file.

The persistent registry

routes.json stores proxy settings, registrations, name sources, and the selected project file. Use -config before the command to select a different registry. This example uses high ports and enables the editor backend:

{
  "suffix": "dev.test",
  "http_port": 18081,
  "https_port": 18443,
  "admin_port": 2021,
  "directory_address": "127.0.0.1:18083",
  "tailnet": false,
  "routes": [
    {"domain": "app.dev.test", "port": 3000}
  ]
}

Reserve distinct, available HTTP, HTTPS, admin, and editor ports. App ports cannot use those ports. Upstreams must accept connections at 127.0.0.1:<port>. The suffix can contain several labels, but each app gets exactly one label before it: app.dev.test works for suffix dev.test; branch.app.dev.test does not.

To inspect or save this registry after applying project-map precedence, run localproxy config export (JSON on stdout), or localproxy config export -o snapshot.yaml (YAML file). See configuration export for format flags, file handling, and portability details.

Apps with Host checks

By default, Caddy preserves the incoming hostname. If an app only accepts localhost, add "localhost_host": true to its registry route and reload. Caddy then sends Host: localhost:<port>. Renaming preserves this setting.

CLI writes and Caddy reloads are separate steps. A failed CLI reload can leave the new registry saved while old routes still run. Fix the reported problem and retry reload. See reload troubleshooting.

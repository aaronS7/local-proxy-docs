REFERENCE / CLI reference

A small command surface.

Commands, flags, and the files they read and write.

Invocation

localproxy [-config routes.json] [-file proxy.yaml|proxy.json] [--tailnet] <command>

Examples use ./bin/localproxy when running from a source checkout. -config and -file go before the command. --tailnet is normalized so it can appear before or after a command; use --tailnet=false to disable it.

Commands

CommandEffect
setup [--dry-run] [--suffix SUFFIX] [--uninstall]Preview, install or remove machine trust, binding permissions and optional .test DNS. --suffix only initializes a new registry. --non-interactive fails rather than requesting administrator access.

dns [--suffix test] [--listen IP:PORT]Run the optional loopback DNS responder, normally managed by setup.
--versionPrint the build version, source commit, and operating system/CPU.

rename <old> <new>Persist an override for an existing route without changing its port.
remove <name>Remove the registration and suppress its port from maps and discovery.
discoverScan listening HTTP ports and persist random names for new apps.
lookup <port|localhost-url>Print the registered domain for a localhost port. Supports text, JSON and YAML.

skill [print | install]Print the Local Proxy skill, or preview and confirm installation of SKILL.md. No registry or Caddy access.

Route mutations regenerate configuration and reload when the configured admin endpoint responds. CLI reload failures can leave saved changes unapplied; see reload troubleshooting.

Lookup and machine-readable output

./bin/localproxy lookup 3000
./bin/localproxy lookup http://localhost:3000/path
./bin/localproxy lookup localhost:3000 --json
./bin/localproxy lookup 'http://[::1]:3000' --format yaml
./bin/localproxy list --json

Default lookup output is one domain and a newline, for example app.test. HTTP(S) URLs must use localhost or a loopback IP. A URL without an explicit port uses 80 for HTTP or 443 for HTTPS. Paths, queries and fragments are ignored. Credentials, remote hosts, unsupported schemes and invalid ports are rejected. Lookup does not resolve DNS or contact the app.

Both lookup and list accept --format text|json|yaml, --json, or --yaml. Choose one format flag; it can appear before or after the lookup input. Global -config and -file still go before the command.

Example JSON for an app registered on port 3000:

{
  "domain": "app.test",
  "port": 3000,
  "localhost_url": "http://localhost:3000",
  "http_url": "http://app.test",
  "https_url": "https://app.test",
  "name_source": "override"
}

Lookup produces one object. List produces an array sorted by domain, including [] when there are no routes. YAML has the same fields and types as JSON. Proxy URLs include the registry's non-default HTTP and HTTPS listener ports; the lookup's plain domain output never includes a port. name_source is override, file, discovered, or an empty string for an unlabeled legacy entry.

domain=$(./bin/localproxy lookup 3000)
./bin/localproxy lookup 3000 --json | jq -r '.https_url'
./bin/localproxy list --json | jq -r '.[].domain'

Both queries read the same merged configuration, including project defaults, manual overrides and suppressed ports. They do not write files, start Caddy or prove that saved routes are running. Missing matches, multiple domains on one port, invalid options and configuration errors exit with status 1, diagnostics on stderr and empty stdout. Help exits with status 0. No match is never silently assigned a new name.

Export configuration

./bin/localproxy config export
./bin/localproxy config export --format yaml
./bin/localproxy config export -o snapshot.yaml
./bin/localproxy config export --json --output snapshot.json
./bin/localproxy config export --yaml -o -

config alone is shorthand for config export. The default is JSON on stdout. --format json|yaml, --json, and --yaml select the format; choose one. -o FILE and --output FILE choose the destination, with - meaning stdout. These flags go after config export; global -config and -file go before config.

SelectionResult
No format or output flagsJSON on stdout
-o snapshot.yaml or -o snapshot.ymlYAML inferred from the filename, case-insensitively
-o snapshot.json, another extension, or no extensionJSON
--format yaml -o snapshot.jsonExplicit YAML wins over the extension
--yaml -o -YAML on stdout

The export contains the complete effective registry after project-map merging: listener ports, suffix, route names and sources, Host overrides, suppressed ports, selected project file, directory backend, and the persisted tailnet setting. Routes are sorted by domain and suppressed ports numerically. Optional default fields are omitted, as in the registry schema; an empty route list is [].

Export reads configuration without contacting Caddy, probing apps or Tailscale, or writing runtime state. It does not prove that Caddy has applied the configuration. JSON can be read again with -config; YAML has matching field names for other tools, but -config still accepts only JSON. This full configuration is different from a flat proxy.yaml project map. The selected project_file path is retained; transferring the export to another machine also requires handling that dependency.

File output leaves stdout empty, replaces regular files atomically, preserves existing permissions, and creates new Unix files with mode 0600. On Windows, files inherit directory ACLs. Parent directories must exist. Export refuses to overwrite the input registry or selected project map, including file aliases, and rejects symlink or nonregular destinations. Invalid configuration or options leave existing output untouched; errors go to stderr and exit nonzero.

./bin/localproxy -config /path/to/routes.json -file /path/to/proxy.yaml \
  config export --format yaml --output snapshot.yaml
./bin/localproxy config export --yaml > snapshot.yaml

With shell redirection, the shell truncates the destination before the CLI runs. Use --output when replacing a file to retain the export command's validation and atomic replacement behavior.

Agent instructions and skill

Both command groups default to print. Output is plain Markdown on stdout, suitable for reading or piping into another tool. Printing does not read the registry, inspect project maps, contact Caddy, or write files.

./bin/localproxy agents
./bin/localproxy agents print
./bin/localproxy skill print

Installation previews the destination and proposed content on stderr, then asks for confirmation. Answer y or yes to apply it. A negative response, blank response, or end of input makes no change. Use --yes only after authorizing the edit, for scripts or automation.

./bin/localproxy agents install
./bin/localproxy agents install --path /path/to/project/AGENTS.md
./bin/localproxy skill install
./bin/localproxy skill install --path .agents/skills/local-proxy

# Explicit approval for a scripted installation:
./bin/localproxy agents install --path /path/to/project/AGENTS.md --yes
OptionMeaning
agents install --path FILEDefaults to AGENTS.md in the current directory, or an existing lowercase agents.md when uppercase is absent. If both exist, select one explicitly.
skill install --path DIRECTORYWrites SKILL.md inside this directory. Defaults to $CODEX_HOME/skills/local-proxy, or ~/.codex/skills/local-proxy when CODEX_HOME is unset.
--yesExplicitly approve installation without prompting. The content preview still appears.
--helpShow command-group or install usage.

The AGENTS installer appends or updates the section between <!-- localproxy:begin --> and <!-- localproxy:end -->. Surrounding instructions and existing file permissions are preserved. Identical installs do nothing. Malformed or duplicate markers, symlink destinations, and edits detected during confirmation fail without replacing the file.

The skill installer replaces only its destination SKILL.md after confirmation and preserves other files in the skill directory. Use $local-proxy in a new agent session after installation. Both instruction documents are embedded in the binary, so no network or source checkout is required. Avoid redirecting printed output over existing instruction files; installation handles preservation and confirmation.

Editor options

./bin/localproxy -config /path/to/routes.json ui \
  --listen 127.0.0.1:18083 \
  --proxy-admin 127.0.0.1:2021 \
  --proxy-config /path/to/.local/caddy.json
OptionDefault / purpose
--listen127.0.0.1:18083. Must use a loopback IP.
--proxy-adminRegistry admin port on loopback. Selects the Caddy instance to update.
--proxy-configOptional path to an instance-specific config snapshot to update for restarts.

ui --tailnet currently has no effect. Persist the option with reload --tailnet or generate --tailnet first. -file is also not applied by the early UI dispatch; establish the selected map with a generating command before starting the UI.

Files and defaults

SettingDefault
Registryroutes.json in the current directory
Suffixlocalhost for new registries; saved configurations are preserved
HTTP / HTTPS ports80 / 443
Caddy admin endpoint127.0.0.1:2021
Generated JSON.local/caddy.json, alongside the registry
Local CA data.local/caddy-data, alongside the registry
Registry lock.local/registry.lock, alongside the registry

Caddy is embedded and selected by default. Set CADDY_BIN explicitly to use an external engine; PATH and adjacent Caddy installations are not selected automatically. Use localproxy caddy version, localproxy caddy list-modules, or localproxy caddy validate --config .local/caddy.json to inspect the embedded engine. Caddy self-update commands are disabled; update Local Proxy to update its embedded Caddy.

Common sequences

./bin/localproxy add app 3000
./bin/localproxy add api 8080
./bin/localproxy rename app studio
./bin/localproxy list
./bin/localproxy remove api

These commands use the current registry and can reload its running Caddy instance. Use the isolated demo to experiment with a disposable registry first.

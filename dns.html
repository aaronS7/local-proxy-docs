GUIDES / DNS & HTTPS

Local names, ready to use.

Understand name resolution, certificate trust, and machine setup.

Localhost by default

New configurations use .localhost: app.localhost opens your app and home.localhost opens the directory. Modern browsers resolve these names to loopback without a DNS installer. Other clients can vary. doctor implements the same special-use localhost mapping; doctor --system-dns checks whether the OS resolver itself supports these names. Existing registries keep their suffix.

Set up your machine

localproxy setup
localproxy up

Run setup as your normal user; it requests administrator access for machine changes. Setup trusts the instance's local CA and grants Linux port-binding permission. On macOS, a launchd helper forwards loopback ports 80 and 443 to the unprivileged proxy; TLS keys stay in your account. The .localhost path makes no DNS changes. up starts the proxy and editable directory together; Ctrl-C stops both. Start your apps separately.

Use setup --dry-run to preview changes. Rerun setup after replacing the executable. Keep a stable registry with -config PATH: machine setup belongs to one CA and suffix, and rejects a different instance until the original setup is removed.

Optional .test domains

localproxy setup --suffix test
localproxy up

--suffix initializes a new registry; it never renames existing routes. dev.test is also supported. Setup installs the embedded DNS responder on loopback, with UDP and TCP support. Unknown names beneath the suffix resolve too, so they can open the directory.

SystemDNS integration
LinuxA systemd service on 127.0.0.55:53 and a scoped systemd-resolved rule. Requires an active resolved stub at 127.0.0.53; conflicting global DNS settings are refused.
macOSA launchd service on 127.0.0.1:53 and /etc/resolver/<suffix>.
WindowsA Windows service on 127.0.0.1:53 and a suffix-specific NRPT rule.

No dnsmasq or source checkout is required. Browser DNS-over-HTTPS settings may need to use the system resolver for .test. Other local DNS services using the selected address and port must be configured separately.

The macOS port forwarder supports HTTP/1.1 and HTTP/2 over TCP. Direct proxy listeners also support HTTP/3. Its internal high ports are stored as http_bind_port and https_bind_port; setup manages these fields.

Exact-name HTTPS certificates

The embedded Caddy engine issues an internal certificate for each requested local name, including unknown names that open the directory. It does not rely on a *.test or *.localhost wildcard. The first connection to a new name may take a moment while its certificate is issued. Unrelated domains are not eligible.

Restart an older running engine to use this behavior. Its existing CA data is preserved. HTTPS still requires trust: Linux setup imports into existing user NSS databases when certutil is available; independent browser stores or managed browser policies may require a manual import.

Windows curl with Schannel may require curl --ssl-revoke-best-effort https://app.localhost: the local CA has no online revocation service. This option retains certificate-chain and hostname verification. See the curl documentation.

Inspect without installing

setup --dry-run writes nothing. The source demo uses temporary files and high ports; its curl examples use --resolve and --cacert to check routing without changing machine DNS or trust.

Keep local trust local

CA data lives at .local/caddy-data beside the registry. The public root is pki/authorities/local/root.crt. Private keys remain in that directory and should stay private and untracked. Setup copies only the public root into the machine trust store.

Stop and remove setup

localproxy stop
localproxy setup --uninstall

Use the same registry as installation. Uninstall removes the managed DNS service and resolver rule, certificate trust and Linux binding capability. Your project files, registry and CA data remain. On macOS, uninstall marks this CA untrusted before deleting its certificate; running setup again restores trust. A separately configured service manager must be stopped through that manager.

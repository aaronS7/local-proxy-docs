REFERENCE / How it works

Go coordinates. Caddy routes.

Follow a request from a local name to its original localhost port.

The request path

REQUEST ROUTING
Browser→Caddy host match→App / directory
DNS and TLS happen before the request can reach an application route.

Caddy matches each registered hostname and proxies to 127.0.0.1:<port>. A terminal fallback returns the generated static directory or proxies to the optional editor server. Both generated HTTP and HTTPS servers use this route list.

The Go process does not sit in the application request path. Choosing Go for this CLI helps with packaging and control operations; app proxy throughput is governed by Caddy, the upstream, and the surrounding system. No benchmark here establishes a Go-versus-Rust proxy advantage.

The configuration path

  1. Read the registry and select a project map.
  2. Merge file defaults, persisted overrides, and discovered names.
  3. Validate names, reserved labels, and port conflicts.
  4. Write generated Caddy JSON and apply it when the command calls for a reload.

CLI mutations use a shared file lock to serialize registry operations. Browser edits add optimistic revision checks so two users cannot silently overwrite each other’s work. Individual file replacement is atomic, but several files and a running Caddy config are not one atomic storage system.

Operational boundaries

The admin endpoint controls Caddy and remains on loopback. The editor is also loopback-only at its own listener. A separate directory listener can share editing access over a tailnet, but --tailnet alone does not create one.

The directory’s Host and CSRF checks protect request boundaries, not user identity. Registry state is not a health check. Project-file reads are immediate, whereas routing changes require applying the configuration. These distinctions explain several review findings.

Where performance work helps

The embedded HTML template is parsed once and reused with per-request data. HEAD directory requests skip rendering and Tailscale subprocesses after configuration and Host validation. Editable Caddy configuration skips generating an unused static page.

These improvements reduce directory and configuration work. Measured microbenchmarks keep those results separate from app proxy throughput.
